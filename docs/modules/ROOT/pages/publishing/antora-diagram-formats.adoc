= Antora diagram formats
:navtitle: Antora diagram formats
:description: Two build-time diagram formats (Mermaid and PlantUML via Kroki→SVG) plus hand SVG and optional runtime Mermaid fallback.

DevCentr docs hubs support **two primary text-diagram formats**, both preprocessed to **SVG at Antora build time** via link:https://docs.kroki.io/[Kroki] (`asciidoctor-kroki`):

[cols="1,2,2"]
|===
| Format | AsciiDoc form | Best for

| Mermaid
| `[source,mermaid]` or `[mermaid]`
| Flowcharts, sequence-ish orientation, quick authoring

| PlantUML
| `[plantuml]` or `[source,plantuml]`
| Sequence, component, and structured UML-style figures
|===

Hand-authored SVG under `docs/modules/*/images/` remains first-class for mockups and brand figures (run skill `fix-docs-encoding` after edits).

== Theme-aware figures (Themed SVG)

Raw Kroki embeds are fixed-color `<img>` assets: page CSS and `html.dark-theme` do **not** reach inside them.
For figures that must track the site dark-mode toggle, post-process renderer SVG in CI:

[cols="1,2,2"]
|===
| Source | Adapter | Contract

| Mermaid (`.mmd` / `mmdc`)
| link:https://github.com/dev-centr/mermaid-svg-css-vars[`@dev-centr/mermaid-svg-css-vars`]
| link:https://github.com/dev-centr/themed-svg[Themed SVG] adaptive + host

| PlantUML (`.puml` / Kroki)
| link:https://github.com/dev-centr/plantuml-svg-css-vars[`@dev-centr/plantuml-svg-css-vars`]
| same
|===

Serve with a `[.themed-svg]` image role so the hub runtime can inline the host SVG.

.Dark-text completeness (build WARN)
****
Adaptive Themed SVG fallbacks must rewrite Mermaid's hardcoded `#my-svg { fill }` and `.label { color }` to `color.text.primary` (see component `diagrams:generate` checks).
The hub playbook loads `lib/verify-themed-svg-dark-mode.js`, which **WARN**s at Antora `contentClassified` when an adaptive SVG still has those hardcoded colors under `prefers-color-scheme: dark`.
Example: `WARN themed-svg dark-mode text: .../agent-cli-auth-flow.svg: root #my-svg fill is a hardcoded color (not color.text.primary var); <text> inherits it in dark mode`
****

These adapters are general-purpose packages in **dev-centr**; Antora importance is compose/recommend (see link:https://github.com/antora-supplemental/antora-facto[antora-facto]), not forks into antora-supplemental.

== Playbook wiring (this hub)

[source,yaml]
----
asciidoc:
  extensions:
    - asciidoctor-kroki
  attributes:
    stem: latexmath
    kroki-server-url: http://127.0.0.1:8000
    kroki-fetch-diagram: true
----

`kroki-fetch-diagram: true` embeds diagram SVG in the published site so readers do not call Kroki at view time.
**Local and CI playbooks share this Kroki URL** so Mermaid/PlantUML render through the same self-hosted gateway (public `https://kroki.io` Mermaid can return **500** intermittently; `asciidoctor-kroki` then WARN-skips the block).

Install: `pnpm add -D asciidoctor-kroki` in the playbook repo.

== Self-hosted Kroki (local + CI)

Local sibling builds and GitHub Actions both use `yuzutech/kroki` + `yuzutech/kroki-mermaid` on `http://127.0.0.1:8000`.

Local:

[source,shell]
----
pnpm kroki:up
pnpm build
pnpm kroki:down
----

That starts `docker-compose.kroki.yml`. Mermaid is a **companion** service — the gateway alone answers **503** for `/mermaid/*`.
CI (`.github/workflows/deploy.yml`) starts the same images as job `services` and waits for health before `antora`.

To force the public server on a one-off build:

[source,shell]
----
pnpm antora --attribute kroki-server-url=https://kroki.io antora-playbook-local.yml
----

== Runtime Mermaid (optional fallback)

Supplemental `site-mermaid.js` still ships for progressive enhancement and for sites that have not enabled Kroki yet.
When Kroki converts a block at build time, the listing becomes an image — the runtime helper finds nothing to re-render (no double draw).

== Facto pack (not Valentus core)

Valentus UI stays a **lean theme**.
Reusable playbook defaults (Valentus + Lunr + stem/math + Kroki diagrams + related essentials) live in the separate compose pack link:https://github.com/antora-supplemental/antora-facto[`antora-supplemental/antora-facto`] — the *de-facto* stack, discovered by pack name like a VS Code extension pack, not forced into the Valentus `v2` rolling tag.
