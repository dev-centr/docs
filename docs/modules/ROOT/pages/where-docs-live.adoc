= Where Documentation Lives
:navtitle: Where Documentation Lives
:description: How the Dev-Centr documentation is structured across repositories and the built site.

This site (docs.devcentr.org) is built by the link:https://github.com/dev-centr/docs[docs] repository, which aggregates content from several repositories:

* **uniconfig** — UniConfig Config Panel (schema-driven config UI). xref:uniconfig::index.adoc[component] · xref:tools/uniconfig.adoc[portal].
* **devcentr** — The main Dev Center application docs: project vision, component specifications, Secrets Manager, publishing, upstream contributions. The app repo can also be built standalone (single-repo build) for development.
* **devcentr.org** — Marketing site docs (SolidStart shell, news/changelog pipelines, Toolchain Advisor, agent skills): xref:devcentr-org::index.adoc[devcentr.org]. Live site: link:https://devcentr.org[devcentr.org].
* **general-knowledge** — Shared, product-agnostic developer reference: tutorials, how-tos, reference, and explanations (Diátaxis-organized). Includes xref:general-knowledge::explanation/architecture/software-product-essentials.adoc[Software Product Essentials] and xref:general-knowledge::explanation/architecture/classes/index.adoc[desktop / web / mobile auxiliary templates]. Peer group **Internet Architecture** (systems altitude): xref:general-knowledge::explanation/internet-architecture/reliability/index.adoc[Internet Reliability] — reference durability and usability of the internet, with deep links to HCI *Labels versus wires* and connectome-fs (not buried under product SPE Architecture). xref:general-knowledge::explanation/languages/index.adoc[Language recommendations] (D, Rust, TypeScript, Julia; comparisons that used to live on Gemini shares). Git workflows, EOL strategy, SSH keys, recommended tools, xref:general-knowledge::reference/ai-studio-tooling-catalog.adoc[AI studio tooling catalog], xref:general-knowledge::how-to/composio-mcp-setup.adoc[Composio MCP setup], xref:general-knowledge::explanation/infrastructure/studio-mcp-install-strategies.adoc[studio MCP install strategies], and similar.
* **business-bootstrap** — Support-systems hub by capability area (Email, Scheduling, Design, Vault, Chat, Funding, Org infra) for **organizations** (not profit-only): xref:business-bootstrap::reference/business-resources.adoc[stack map], xref:business-bootstrap::reference/defaults-by-org-stage.adoc[defaults by stage], Cal.com/Cal.diy, Penpot, Bitwarden/Vaultwarden, Mattermost self-host, xref:business-bootstrap::funding/explanation/oss-funding-landscape.adoc[OSS funding landscape], xref:business-bootstrap::funding/explanation/donation-ask-ideas.adoc[donation ask ideas] (canonical guide on link:https://nonprofit-resources.org/guides/donate-page-as-a-ledger[Nonprofit Resources]), human vs product email, DMARC, Pulumi `infra` pattern.
* **infra-template** — Reusable Pulumi + Antora skeleton for org `infra` repos.
* **templates** — Standardized project templates and usage guides.
* **easy-installer** (product **Ibex**) — Install Builder Extension: installer projects, in-place PATH, plugin ABI, shell hooks.
* **msi-generator** — MSI/MSIX generator documentation (engine used by Ibex plugins).
* **switchyard** — Windows file-association switchyard (snapshot / icon lock / file-router roles).
* **issues-browser** — Forge metadata index/backup (GUI/CLI/daemon/tray); integrates with RepoDrive.
* **repo-drive** — Standalone virtual forge drive (GUI + tray + FUSE/WinFsp); sparse repos, schema, VCS toolbox.
* **connectome-fs** (partner org) — Graph-native filesystem substrate; docs live on link:https://connectome-fs.github.io/connectome-fs/[connectome-fs.github.io], not aggregated into this hub. Practitioner cross-links remain in general-knowledge.
* **agentic-email-integration** — Own-your-inbox Gmail integration (Himalaya + agents). Complementary MCP connectors: xref:tools/composio.adoc[Composio].
* **fixnow-dev** — FixNow pressure-driven issue tracking: AI value scoring, countdown badges, and resolution verification.
* **scriptbook** — PlayTime engine + Scriptbook app: play CentrMark `.cmk` playbooks (intents, not shell translation). xref:scriptbook::index.adoc[Scriptbook] · xref:general-knowledge::explanation/infrastructure/abstract-playbooks.adoc[Abstract playbooks].
* **equivalence-engine** — Catalog lookup and code-domain rewrites. Host Awareness bake is CI-time; runtime PlayTime must not ask it what OS it is. xref:equivalence-engine::index.adoc[Equivalence Engine].

Org-wide roadmap and activity log live here in the **docs** repo so they stay in one place across all projects. Repo-specific task lists (e.g. devcentr's root `TODO.adoc`) remain in each repository for day-to-day work; the central xref:todo-roadmap.adoc[Todo & Roadmap] summarizes themes and the xref:activity-log.adoc[Activity log] records notable updates.
